# 瞄准输出整形: 压枪平滑

本档固定"后坐力工况下瞄准输出平滑度"这一通道的设计事实与结论: 主方案 (§1)、备选
与已否决路线 (§2)、评测口径 (§3)、未决事项 (§4)。每一条路线写成"是什么 / 物理依据 /
硬伤 / 结论"; 常数只以"有出处或可复现的推导规则"的形式出现, 未定的量一律进 §4,
不落成拍出来的固定值。

| 路线 | 结论 |
|---|---|
| 开火门控的 Y 通道专用压枪律 | **主方案** (§1) |
| 垂直裕度 (band-with-drift) | 被主方案吸收; 保留为纯位置域兜底 (§2.1) |
| "每 x 秒最多变化 N 次"式节流 | 已否决 (§2.2) |
| 误差调制的低通 τ(\|e\|) | 非开火期的补充候选 (§2.3) |
| 后坐力图案前馈 | 可行且可叠加, 属另一个量级的工作 (§2.4) |
| arena 人类通道建模 | 契约级决定, 单独立项 (§2.5) |

## 0. 问题与判据

### 0.1 现象

后坐力场景下武器射速慢、每发跳得高。人类的压枪是**平滑**的: 提前预判、以大致恒定的
速率把准星下压, 同一段补偿位移摊在整个发间隔里。控制律则**反应过快** —— 它在两发之间
就把准星压回目标点, 速度指令因此近似**矩形脉冲**: 一瞬间压下去, 随后停住等下一发,
屏幕上的准星运动呈"一顿一顿"。

鼠标输出与手柄输出都有这一现象, 手柄上更显眼: 摇杆的物理运动是连续的, "冲一下再静止"
这种运动人类在物理上打不出来。

### 0.2 判据 (什么算"好")

| # | 判据 | 口径 |
|---|---|---|
| ① | **平滑度** | §3 的平滑度指标; 命令序列的时间分布, 与"准星离目标多远"无关 |
| ② | **不牺牲精度** | 竖直 RMSE / 过冲 / 发散判据不得变差, 口径与标准评测组一致 |
| ③ | **拉枪不受影响** | 大误差、非开火期的快速响应必须原样保留 |
| ④ | **全工况不退化** | 快慢射速 × 大小后坐力的组合下都不得退化 |

判据 ②③④ 是准入条件而不是权衡项: 任何"平滑"只能在与原律逐位一致的精度与拉枪行为
之上取得 (契约: 失配与闪烁是任何机制的准入门槛)。

## 1. 主方案: 开火门控的 Y 通道专用压枪律

### 1.1 结构

| 项 | 内容 |
|---|---|
| 门控信号 | 复用现有 `-k fire/ads/both` 的开火触发信号; **不新增输入通道** (每个游戏通常只有一个开火键) |
| 按下期间 X 轴 | 继续走原律, **满权** —— 横向追踪不受影响 |
| 按下期间 Y 轴 | 切到专用压枪律: **重低通 + 保留 I 项** |
| 松开 | 立即把 Y 交还原律 |

### 1.2 关键物理: 后坐力是要跟着走的低频位移, 不是要滤掉的噪声

相机被顶起时, 画面里的世界(含目标)整体下移 —— 准星必须**跟着下移**才能继续瞄着目标。
因此压枪通道的低通必须 **DC 增益 = 1**(通直流、滤交流): 让"平均下压速率"通过, 把"每发
的阶跃"滤掉。

反过来做 —— 把垂直误差本身滤掉或忽略 —— 等于不压枪: 准星眼睁睁向上跑。这是本方案最
容易做错的一处; 平滑度指标的实现必须建立在这条物理之上, 否则测的是一个不压枪的律。

### 1.3 该结构同时覆盖"垂直裕度"的目标

重低通在两个尺度上给出裕度想要的两种行为: 对小幅快速误差**几乎不响应**(不积极压枪),
对持续误差仍**经 DC 路径收敛**(慢慢往点走)。因此主方案与裕度不做叠加 —— 裕度不需要
单独加 (它的残留价值见 §2.1)。

### 1.4 参数出处

平滑时间常数 **τ = K × 发间隔**; 发间隔**在线测**, 不拍固定值:

- **辨识信号**: 开火期间 Y 误差序列的周期性 → 自相关 / 峰间隔。
- **回退尺度**: 测不到周期性(单发点射)时用环路延迟 L 或帧周期作时标 (具体取哪一个见 §4)。
- **K 的选择规则 (可复现)**: K 是无量纲设计选择, 口径为"在 §3 平滑度指标上把每发阶跃压到
  与发间隔同量级, 同时竖直 RMSE / 过冲不劣于原律"。K 越大越平滑、DC 路径收敛越慢, 两条
  都单调, 所以取值是该口径下的**边界点**, 由 arena 后坐力组给出。

### 1.5 三个必须解决的硬问题

| # | 问题 | 要求 |
|---|---|---|
| 1 | **无扰动切换 (bumpless transfer)** | 进/出开火时两套律的 Y 状态(积分器、预测器 Y 分量)必须交接。不交接则按键瞬间引入新的跳变, 可能比原现象更显眼 —— 门控的好处会被切换瞬态抵消 |
| 2 | **两轴在现有律里是耦合的** | `ff_pi_acc` 的 I 门用 `r = hypot(ex, ey)`、FF 信任门用 `max(csx, csy)` —— **共享门**。"Y 单独换律"因此不是外挂一层, 必须在律内部把 Y 通道的门**切开**; 切口必须在 arena 失配带组 + FPS 组上证明不退化 |
| 3 | **发间隔在线估计的鲁棒性与可辨识性** | 极不规律射击下的退化行为与回退必须有明确答案, 不许静默失效 |

### 1.6 已知代价

开火期间垂直带宽降低 → 对跳跃 / 上下移动目标的**垂直追踪变差**。代价接受, 且与人类
一致: 人类压枪时同样不追垂直运动。因此该代价不构成对 §0.2 判据 ③ 的违反 —— 判据 ③
针对的是非开火期与大误差的响应。

## 2. 备选与已否决路线

### 2.1 垂直裕度 (band-with-drift)

- **是什么**: 以瞄准点为中心的垂直容差带, 以**瞄准点百分比域**表达 (例: 瞄点 65 → 容差
  55–75, 即以目标框高比例定义的 ±10 个点), 因此**随距离自动缩放** (框高 ∝ 1/d)。
- **物理依据 / 机制**: 带内降低 P 增益 (连续过渡, 避免边界抖振), 保留 I (慢慢靠近)与
  FF (追移动目标)。
- **硬伤**: 持续开火时准星可能**贴在裕度边缘**, 形成系统性垂直偏差 (≈ ±10% 框高, 10m 处
  约 ±17px)。
- **结论**: 被 §1 的主方案**吸收** —— 重低通同时给出"不积极"与"慢慢靠近", 用更少的常数
  取得同一效果。保留价值: 若 §1 的 τ 自适应在个别武器上失效, 裕度是**纯位置域**的兜底,
  不依赖任何时间尺度的在线辨识。

### 2.2 "每 x 秒最多变化 N 次"式节流 — 已否决

- **是什么**: 给输出指令加一个变化频率上限。
- **硬伤**: ① "变化次数"不是物理量, 无法区分 1px 抖动与 50px 修正; ② 输出被限流期间积分器
  继续累积 → 解除限流时过冲 (与"共享执行器非对称行程"同一个 anti-windup 病灶); ③ 离散
  节流器本身会产生**极限环**。
- **结论**: 已否决。三条硬伤中的任何一条都足以排除, 且 ②③ 是结构与生俱来的, 不是参数问题。

### 2.3 误差调制的低通 τ(\|e\|)

- **是什么**: 小误差重滤、大误差不滤; 尺度取自在线位置噪声 σ 与 L。
- **关系**: 与主方案部分重合 (都把小误差当"不值得响应"的信号)。
- **结论**: 不与主方案竞争开火期的通道。若"开火门控 + 自适应 τ"不足以覆盖**非开火期**的
  抖动, 作为非开火期的补充候选。

### 2.4 后坐力图案前馈

- **是什么**: 学每把武器的后坐力图案, 提前平滑预压。
- **物理依据**: 理论最优 (零滞后) —— 图案已知时不需要从误差里发现扰动。
- **硬伤 / 代价**: 需要图案数据, 以及跨武器 / 跨游戏的泛化, 属另一个量级的工作。
- **结论**: 与 §1 不冲突 (可叠加), 但不作为当前路线。

### 2.5 arena 中的人类通道建模 — 单独立项

- **是什么**: 在 arena 里建模人的手 / 摇杆通道 (人类也在压枪, 也下发指令)。
- **为什么不能顺手做**: 人手与律**共用执行器**; 真实固件靠"账本"(含人类指令)做自身运动
  补偿, 而 arena 的最小接口只给律"观测"、不给"总指令"。要忠实模拟"双重补偿"的交互, 必须
  先扩接口。
- **结论**: 扩接口是**契约级决定**, 需单独决策, 不宜顺手加进后坐力场景族。

## 3. 评测基础 (在 arena 侧建立)

评测基础由三块构成:

| 块 | 内容 |
|---|---|
| **后坐力场景族** | 射速 × 每发落差 网格, 覆盖慢射速 / 高跳 |
| **平滑度指标** | 速度指令台阶数 / 秒、符号反转数 / 秒、jerk RMS、**每发响应完成比例** |
| **精度代价指标** | 竖直偏差 / 过冲 / 发散 |

**每发响应完成比例**是本组最直接量化"一顿一顿"的一条: 以每发时刻对齐, 人类应接近
**1.0** (整段间隔匀速下压), 而律会是小值 (前段就压完, 其余时间停住等下一发)。

该组作为**独立评测组**加入 arena; 现有三组默认评测 (`arena.eval` / `arena.integrate` /
`arena.fps_eval`) 保持逐位不变 (契约: 共享评测组不为实验让路)。指标与场景的实现细节落在
arena 自己的模块里, 本档只固定口径。

**主方案落地前必须**: 在 arena 里实现为 `_wip_` 律, 用上述指标 + 四组评测 (现有三组 +
后坐力组) 验证, 再谈移植。
